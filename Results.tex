\vspace{4cm}
With the theoretical framework for gravitational lensing 
of GWs now established, including the geometric optics 
formalism, the signatures of strong lensing on GW signals, 
and the joint PE approach that exploits lensed image pairs to improve sky localization, we are in a position to present the original results of this thesis. Chapter~\ref{ch:simulation} describes the simulation setup and the strongly lensed BBH population generated with \textsc{LeR}. Chapter~\ref{Parameter_estimation_pipeline} presents the PE pipeline. Each image is first analyzed individually with \textsc{Bilby}, and the two images of each event are then analyzed jointly with \textsc{Hanabi}, which coordinates the coherent analysis of the image pair, sharing the intrinsic binary parameters between images while sampling the lensing parameters, on top of the \textsc{Bilby} inference backend. The chapter also describes the automation infrastructure deployed on the Picasso HPC cluster. Finally, Chapter~\ref{Skyloc} presents the sky localization results, comparing the 90\% credible sky area obtained from single-image and joint analyses across the final set of analyzed events.

\chapter{Simulation setup and implementation}
\label{ch:simulation}

This chapter describes the construction of the lensed 
BBH population used as input to the PE pipeline. The simulation proceeds in two stages: first, a large Monte Carlo (MC) population of strongly lensed BBH events is generated with \textsc{LeR} v0.4.2 
\cite{phurailatpam2026lerlvkligovirgokagracollaboration}, and then a realistic detectability filter is applied to select the subset of events that would be observed by the H1 and L1 detectors under O5 sensitivity conditions.

\section{Lensed BBH population with \textsc{LeR}}
\label{sec:LER_population}

\textsc{LeR} (LVK Event Rate calculator) is a 
Python framework for the joint simulation and rate 
computation of unlensed and strongly lensed GW 
populations \cite{phurailatpam2026lerlvkligovirgokagracollaboration}. It integrates source and lens population sampling, lens equation solving via \textsc{lenstronomy} \cite{lenstronomy}, and detector selection into a single reproducible pipeline. All lensing calculations are performed in the geometric optics regime and under the thin lens approximation, both of which are valid for galaxy-scale lenses in the LIGO frequency band (see \S\ref{sec:lensing_intro}).

The simulation is initialized with the following 
configuration, specifying the detector network, 
noise curves, and waveform approximant:

\begin{lstlisting}[style=numpyStyle]
ler = LeR(
    npool=6,
    event_type="BBH",
    ifos=['L1', 'H1'],
    psds={'L1': 'T2500310-v2_O5a_strain_psd.txt',
          'H1': 'T2500310-v2_O5a_strain_psd.txt'},
    waveform_approximant="IMRPhenomXPHM",
    spin_zero=False,
    spin_precession=True,
)
\end{lstlisting}

Here, \texttt{npool} sets the number of parallel worker 
processes used for the MC sampling and SNR 
calculations. The simulation was run in a Jupyter 
notebook on the CIT JupyterHub, using the \texttt{igwn} 
conda environment (Python 3.11.14) distributed via 
CVMFS, with 48 CPU cores available. The \texttt{event\_type="BBH"} argument selects the BBH source population model described in Table~\ref{tab:LER_params}, as opposed to the BNS or NS-BH options also supported by \textsc{LeR}. The \texttt{ifos} argument specifies the detector network over which the network SNR $\rho_\mathrm{net}$ (\S\ref{sec:matched_filtering}) is computed, here restricted to the two LIGO detectors, H1 and L1.

The \texttt{psds} argument sets the noise curve assigned to each detector, here the O5a design sensitivity PSD \cite{O5PSD}. This choice is motivated by the goal of simulating a realistic future observing scenario. The default PSD in \textsc{LeR} approximates O4 sensitivity, but no strongly lensed events were detected in O4. Simulating at O5a sensitivity instead, the first epoch of the O5 run with a BNS range of 225\,Mpc \cite{O5PSD}, provides a more informative and forward-looking setting for this study. Figure~\ref{fig:psd_O5a} shows the projected O5a strain sensitivity curve used in this work, compared against the L1 O4 sensitivity achieved in September 2024 and the later O5b and O5c projections.

The \texttt{waveform\_approximant} argument selects 
\texttt{IMRPhenomXPHM} \cite{IMRPhenomXPHM} for the SNR 
computation, which incorporates spin precession and 
higher-order multipole moments. The population presented here uses the original release of this model, with no additional \texttt{waveform-arguments-dict} options passed to \textsc{LeR}. A more recent variant \cite{Colleoni:2024knd} refines the treatment of precession and the final-spin prescription through additional arguments,
\begin{lstlisting}[style=numpyStyle]
waveform-approximant = IMRPhenomXPHM
waveform-arguments-dict = {"PhenomXHMReleaseVersion": 122022,
                            "PhenomXPFinalSpinMod": 2,
                            "PhenomXPrecVersion": 320}
\end{lstlisting}
but this improved configuration was not used for the population generation in this work. Finally, \texttt{spin\_zero=False} enables non-zero component spins in the source population, and \texttt{spin\_precession=True} allows for spin tilts misaligned with the orbital angular momentum, so that the resulting waveforms include precession effects. Both are necessary for the spin parameters listed in Table~\ref{tab:LER_params} to be sampled rather than fixed to zero.

The population is generated by drawing events in 
batches of 20\,000 until 500 strongly lensed 
detectable events are collected, each requiring 
that at least two images independently satisfy 
$\rho_\mathrm{net} \geq 10$:

\newpage
\begin{lstlisting}[style=numpyStyle]
lensed_params = ler.selecting_n_lensed_detectable_events(
    size=500,
    batch_size=20000,
    snr_threshold=10,
    num_img=2,
    resume=False,
    output_jsonfile="n_lensed_params_bbh.txt",
)
\end{lstlisting}

The SNR threshold of $\rho_\mathrm{net} \geq 10$ and 
the requirement of at least two detectable images follow standard detection criteria adopted in GW searches, so that the resulting population reflects events that a real detector network could plausibly identify and confidently claim as lensed, rather than a theoretical population extending down to marginal or sub-threshold significance.

A total of approximately 152\,000 candidate events 
were drawn to collect the 500 detectable ones, 
yielding a total lensed event rate of 
$\mathcal{R}_L \approx 0.75\,\mathrm{yr}^{-1}$ 
for this detector configuration and sensitivity. 
This value is consistent with early forecasts for 
second-generation detector networks at design-like 
sensitivity, which span roughly $0.1$-$10\,\mathrm{yr}^{-1}$ 
depending on the assumed high-redshift merger rate and 
detector network \cite{Wierda_2021}, and is somewhat lower than forecasts for the full three- or four-detector network, reflecting the more limited H1+L1 configuration adopted here.


\section{Injected parameter distributions}
\label{sec:injected_params}

The 500 events produced by \textsc{LeR} represent the strongly lensed population detectable under ideal observing conditions. To obtain a more realistic injection set, a duty cycle filter is applied: for each image of each event, both H1 and L1 are independently activated with probability 
$p_\mathrm{det} = 0.70$, reflecting typical O4 
single-detector duty cycles \cite{GWTC5}. An image is 
retained only if both detectors are simultaneously active and $\rho_\mathrm{net} \geq 10$. Events with fewer than two surviving images are discarded; when more than two images survive, only the two with the highest network SNR are kept. After applying this filter once to the fixed 500-event 
population, 157 events are selected as the final injection set analyzed with \textsc{Bilby}. Table~\ref{tab:selection_funnel} summarizes the successive stages of this selection process, from the initial MC draws performed by \textsc{LeR} to this final injection set.

\section{Pipeline overview}
\label{sec:pipeline_overview}


This chapter presents the PE pipeline built on the injection set described in Chapter~\ref{ch:simulation}, together with the automation infrastructure used to run it for all 157 events. Figure~\ref{fig:pipeline_diagram} places this pipeline within the full analysis developed in this thesis, from the population generation of Chapter~\ref{ch:simulation} (Stage~1) to the sky localization results of Chapter~\ref{Skyloc} (Stage~4). The rest of this section focuses on Stages~2 and~3: the automated generation of \textsc{Bilby}/\textsc{Hanabi} \texttt{.ini} files, and the single-image plus joint PE itself.

\begin{figure}[h!]
    \centering
    \includegraphics[width=\linewidth]{Figures/diagrama_pipeline_reduced_bo.pdf}
    \caption[Overview of the full analysis pipeline]{Overview of the full analysis pipeline developed in this thesis. Stage~1 (\S\ref{sec:LER_population}-\S\ref{sec:injected_params}): the lensed BBH population is generated with \textsc{LeR} and reduced from 500 detectable events to the final injection set of 157 through the duty cycle and SNR selection process (Table~\ref{tab:selection_funnel}). Stage~2 (\S\ref{sec:automation_picasso}): \texttt{Generator\_inis\_lenskyloc.py} converts each event's injected parameters into single-image and joint \texttt{.ini} configurations and the corresponding SLURM scripts. Stage~3 (\S\ref{sec:bilby_config}-\S\ref{sec:hanabi_joint}): each image is analyzed independently with \textsc{Bilby}, then jointly with \textsc{Hanabi}, sharing the intrinsic source parameters and sky location while keeping each image's luminosity distance independent. Stage~4 (\S\ref{sec:skymap_generation}-\S\ref{sec:skyloc_comparison}): sky maps are generated from the posteriors and the recovered 90\% credible areas are compared between single-image and joint analyses.}
    \label{fig:pipeline_diagram}
\end{figure}

Starting from the filtered population \texttt{n\_lensed\_params\_bbh\_filtered.txt} produced in \S\ref{sec:injected_params} (Stage~1), a single script, \texttt{Generator\_inis\_lenskyloc.py}, generates for every event the two single-image \texttt{.ini} configurations, the joint \texttt{.ini} configuration, and the \href{https://slurm.schedmd.com/overview.html}{SLURM} scripts needed for the steps described below, populating priors and injection parameters directly from the corresponding \textsc{LeR} output (Stage~2, \S\ref{sec:automation_picasso}).

Each single-image \texttt{.ini} file is analyzed independently with \texttt{bilby\_pipe} \cite{bilby_pipe_paper}, using the lensed waveform source model provided by \textsc{Hanabi} (\S\ref{sec:bilby_config}). This yields, for every event, two independent posterior distributions, one per image. Once both single-image jobs have completed, the joint \texttt{.ini} file is submitted with \texttt{hanabi\_joint\_pipe} (\S\ref{sec:hanabi_joint}), which jointly analyzes the image pair, sharing the intrinsic source parameters and sky location between images while sampling the lensing parameters, on top of the same \textsc{Bilby} inference framework used for the single-image runs.

From this point the pipeline splits into two independent post-processing tracks. In the first, the joint posterior, together with the single-image data realizations, is passed to \texttt{hanabi\_\allowbreak postprocess\_\allowbreak result}, which recomputes the single-image and network SNRs consistently across the single and joint analyses; a dedicated script then extracts these recovered SNRs into a summary table for each event, later combined across all events for the SNR consistency checks of \S\ref{sec:parameter_recovery}. In the second track, the single-image and joint posteriors are combined with \textsc{PESummary} \cite{PESummary} into a single metafile, from which sky maps are generated for each image and for the joint analysis using \texttt{ligo-skymap-from-samples}, \texttt{ligo-skymap-stats}, and \texttt{ligo-skymap-constellations}, providing the 90\% credible sky areas and the constellation localization compared between single-image and joint analyses in Chapter~\ref{Skyloc}.

The entire pipeline, from \texttt{.ini} generation to job submission and the SNR post-processing track, is automated on the \href{https://www.scbi.uma.es/web/es/supercomputacion/\#documentation}{Picasso HPC cluster} (SLURM scheduler); the sky-map track is run separately, as described in \S\ref{sec:automation_picasso}.


\section{Single-image analysis with \textsc{Bilby}}
\label{sec:bilby_config}

As introduced in \S\ref{sec:pipeline_overview}, each image is analyzed with \texttt{bilby\_pipe} \cite{bilby_pipe_paper} as an isolated signal, characterized by its own data segment, noise realization, and set of extrinsic parameters. The \texttt{.ini} configuration is generated automatically for each image from a shared template (\S\ref{sec:automation_picasso}). Table~\ref{tab:bilby_settings} summarizes the detector and sampler settings common to all 157 events.

The three parallel runs (\texttt{n-parallel}) are independent full \textsc{Dynesty} analyses combined into a single posterior to mitigate sampler-to-sampler variance, while \texttt{npool} parallelizes the likelihood evaluation within each individual run and matches the number of CPUs requested per SLURM job.

The same O5a PSD used to generate the population with \textsc{LeR} (\S\ref{sec:LER_population}) is adopted for the analysis, so that the noise assumptions are consistent between simulation and recovery. Unlike the data duration, which is fixed for the whole population in \textsc{LeR}, the segment duration adopted for each image is computed individually from its injected component masses and spins, using \textsc{LALSimulation}~\cite{lalsuite} bounds on the merger and ringdown time together with the expected waveform length at $f_{\min}=20$\,Hz, rounded up to the next power of two. This keeps each analysis as short as the signal allows without truncating the inspiral, rather than using a single conservative duration for the whole population.

The injected and recovered waveforms both use the \texttt{IMRPhenomXPNR} approximant \cite{IMRPhenomXPNR}, rather than the \texttt{IMRPhenomXPHM} approximant used by \textsc{LeR} to generate the population and compute the detection SNRs that define the selection process of \S\ref{sec:injected_params}. This choice is intentional: \texttt{IMRPhenomXPHM} is computationally cheap and sufficiently accurate for the population-level detectability calculation performed by \textsc{LeR}, whereas \texttt{IMRPhenomXPNR} incorporates precession effects calibrated against NR simulations and is the more accurate of the two, better suited for PE, following standard practice in recent LVK analyses. For the parameter ranges considered here, the two models are expected to agree closely, so this choice between the population-selection and PE stages is not expected to introduce a significant waveform-systematics effect.

The waveform is generated through \textsc{Hanabi}'s lensed source model, \href{https://github.com/ricokaloklo/hanabi/blob/master/hanabi/lensing/waveform.py}{\texttt{hanabi.\allowbreak lensing.\allowbreak waveform.\allowbreak strongly\_lensed\_BBH\_waveform}}, which implements the lensed strain expression of \S\ref{sec:strong_lensing}, combining the intrinsic \texttt{IMRPhenomXPNR} waveform with an image-dependent amplitude and Morse phase factor. In the single-image configuration this factor is fixed to \texttt{image\_type=1} (Type I, a minimum of the Fermat potential) rather than treated as a free parameter. Type I images carry no Morse phase shift ($n=0$, \S\ref{sec:strong_lensing}), so their waveform is identical in phase to an ordinary unlensed signal; the only lensing imprint, an amplitude rescaling and a shifted arrival time, is already absorbed into the standard \texttt{luminosity\_distance} and \texttt{geocent\_time} parameters. The single-image prior fixes \texttt{image\_type} to this value regardless of the true injected type, since doing so does not significantly bias the recovery of the remaining parameters. Each image is thus analyzed as if it were an ordinary CBC signal; identifying the true image type of each image, together with the relative magnification between them, is instead the specific role of the joint analysis (\S\ref{sec:hanabi_joint}), which samples \texttt{image\_type} independently for each image from a discrete prior.

The remaining priors follow standard choices for BBH PE: a chirp mass prior adapted individually for each event to a $\pm30\%$ range around its injected value (rather than a single wide range for the whole population, which would waste live points on regions of parameter space far from every event's true chirp mass), mass ratio and component-mass constraints, uniform spin magnitudes and precession angles, an isotropic sky location, and a $50$-$20\,000$\,Mpc uniform luminosity distance prior; the full \texttt{prior-dict} is reproduced in Appendix~$\S$\ref{implementataion_pipeline}.



\section{Joint analysis with \textsc{Hanabi}}
\label{sec:hanabi_joint}

As introduced in \S\ref{sec:pipeline_overview}, the joint analysis is performed with \texttt{hanabi\_joint\_pipe}, treating the two images of an event as two triggers of the same underlying source rather than as independent signals, with each trigger pointing to its corresponding single-image \texttt{.ini} file and otherwise inheriting its own data segment, noise realization, and PSD. The parameters shared between the two images are the intrinsic binary parameters (masses and spins), the sky location, the inclination, the polarization angle, and the coalescence phase, reflecting the fact that both images are gravitationally lensed copies of the same source. The luminosity distance, by contrast, is fitted independently for each image.

Formally, \textsc{Hanabi}'s lensing model requires specifying both a relative magnification and an image type for each image. Table~\ref{tab:hanabi_lensing_priors} summarizes these lensing-specific priors: the relative magnification is fixed to $1$ for both images (not sampled), since its physical content is already captured by the two independently fitted luminosity distances discussed above, while the image type is the only genuinely free lensing parameter, sampled independently for each image from a discrete uniform prior over the three Morse-index classes introduced in \S\ref{sec:strong_lensing}.

Sharing the sky location across two images observed at different times, typically separated by minutes to months (Figure~\ref{fig:timedelay_hist}), is the key mechanism behind the improvement in sky localization: the Earth's rotation between two arrival times changes the detectors' antenna pattern for the same fixed $(\alpha,\delta)$, effectively acting as a longer effective arm separation for triangulation (\S\ref{sec:joint_PE_skyloc}).

The joint likelihood is evaluated over both images simultaneously, using the same sampler settings as the single-image runs (Table~\ref{tab:bilby_settings}), but with substantially higher resource requirements, reflecting the added cost of a coherent likelihood evaluated across two detectors and two images: $180$\,GB of memory and a $71.5$\,h wall-time limit, compared to $110$\,GB and $48$\,h for each single-image run.


\section{Automation and infrastructure on Picasso}
\label{sec:automation_picasso}

Running this pipeline for all 157 events relies on two components: a script that generates every configuration and job file automatically, and a two-stage submission mechanism that enforces the job dependencies of \S\ref{sec:pipeline_overview}. Jobs execute directly inside a dedicated \texttt{conda}/\texttt{miniforge} environment (\href{https://github.com/XxavierGarcia/TFM_reproducibility_material/blob/main/environment_full.yml}{\texttt{hanabi\_bilby260}}) on Picasso, whose exact specification is provided for reproducibility.

\subsection{Configuration and script generation}

Beyond the duration and chirp-mass prior already computed for each event (\S\ref{sec:bilby_config}), \texttt{Generator\_\allowbreak inis\_\allowbreak lenskyloc.py} populates the \texttt{injection-dict} of both single-image templates directly from the corresponding \textsc{LeR} parameters, mapping, e.g., \texttt{effective\_\allowbreak luminosity\_\allowbreak distance} (the magnification-rescaled apparent distance of Eq.~\eqref{eq:apparent_DL}) to \texttt{luminosity\_\allowbreak distance}, and \texttt{effective\_\allowbreak geocent\_\allowbreak time} (the lensed arrival time of Eq.~\eqref{eq:apparent_tc}) to \texttt{geocent\_time}, so that each image is injected with its own apparent extrinsic parameters rather than the source's true values. Appendix~$\S$\ref{implementataion_pipeline} reproduces a representative single-image and joint \texttt{.ini} pair.

\subsection{Submission and job dependencies}

Job submission is split into two stages. The first, \texttt{submit\_all\_part1.sh}, submits the two single-image \texttt{bilby\_pipe} jobs for each event, followed by the joint \texttt{hanabi\_joint\_pipe} job with an explicit SLURM dependency on both single-image job IDs. The second stage, \texttt{submit\_all\_part2.sh}, runs after the first stage completes and launches the SNR-recovery track described in \S\ref{sec:pipeline_overview}.

The sky-map track, generating \textsc{PESummary} pages and sky maps for every event, is instead run on \href{https://computing.docs.ligo.org/guide/computing-centres/cit/}{LIGO's computing cluster at Caltech (CIT)} using \href{https://htcondor.readthedocs.io/en/latest/}{HTCondor}~\cite{HTCondor}, within the \href{https://computing.docs.ligo.org/conda/}{IGWN Conda Distribution}: \texttt{Pesummaries\_automated\_condor\_all.py} and \texttt{Skymap\_condor.py} are each launched as an HTCondor job array of 157 processes, generating the summary pages and sky maps for all events in parallel. The PE itself, both single-image and joint, was always run on Picasso and never on CIT; only this post-processing track uses HTCondor, since the version of \textsc{PESummary} available in the Picasso environment produced errors, while the \texttt{igwn} environment on CIT ran it correctly. The complete pipeline code, including both the Picasso and CIT branches, is publicly available at \url{https://github.com/XxavierGarcia/TFM_reproducibility_material}.

\subsection{Incomplete events}
\label{sec:incomplete_events}

The joint analysis is the most expensive step of the pipeline, requiring up to $71.5$\,h of wall time per event (\S\ref{sec:hanabi_joint}). Partway through the production run, the project's total compute allocation on Picasso was exhausted; once that happens, the cluster downgrades the project's priority and caps the maximum wall-time allowed for new jobs at $24$\,h, below what the remaining joint jobs required. The last seven joint analyses\footnote{Events \texttt{inj110}, \texttt{inj115}, \texttt{inj118}, \texttt{inj137}, \texttt{inj138}, \texttt{inj142}, and \texttt{inj150}.} were interrupted mid-run as a result. The next allocation period was not due to begin for approximately two months, and rather than delay the analysis by that much to recover seven events, it was finalized with the $150$ events that had completed successfully. This loss of $7$ out of $157$ events is a consequence of the compute allocation available at the time, not a scientific selection criterion, and does not bias the final sample in any systematic way tied to source or lens parameters.





\section{Parameter recovery and validation}
\label{sec:parameter_recovery}

This section evaluates how well the pipeline recovers the injected parameters of the 150 successfully analyzed events: first through a qualitative view of the recovered joint mass posteriors across the sample's SNR range, then through a direct comparison of the full joint and single-image posteriors for a few representative events (shown for the complete sample in Appendix~$\S$\ref{app:violins}), followed by systematic residual checks against the injected values for every recovered parameter, and finally through a quantitative look at the mass bias introduced by gravitational lensing, together with an attempt to correct it.

Figure~\ref{fig:mass1_mass2_recovery} shows the recovered $(m_1,m_2)$ 90\% credible contours for six representative events spanning the joint network SNR range of the sample ($\rho_\mathrm{net}$ from $13.1$ to $60.8$), overlaid on the contours of the remaining events in grey. The two examples with the lowest SNR, \texttt{inj084} and \texttt{inj052}, show visibly elongated, curved contours: the leading-order phase evolution constrains mainly the chirp mass $\mathcal{M}$, so individual masses remain only weakly determined along lines of near-constant $\mathcal{M}$, and this degeneracy widens as the SNR decreases. The examples with higher SNR, in particular \texttt{inj117} ($\rho_\mathrm{net}=60.8$), instead recover both masses precisely. Masses are shown here in the detector frame $(1+z)m_i$, rather than the source frame reported in LVK catalogs \cite{GWTC5_methods}. In this analysis, each image's luminosity distance is sampled independently rather than sharing a common source distance across the pair, so what the posterior actually constrains for each image is the effective distance, $D_{L}^{\mathrm{eff}}=D_{L}^{\mathrm{true}}/\sqrt{|\mu|}$, consistent with how it was injected (\S\ref{sec:automation_picasso}). With only the two images' apparent distances, the true source distance $D_L^{\mathrm{true}}$ and the magnification $\mu$ of each image cannot be separated: two observed quantities constrain three unknowns, and additional information (an electromagnetic counterpart or an independent lens model) would be needed to break this degeneracy \cite{Poon2025_lens_reconstruction}. Converting the apparent distance directly to a redshift, and hence to a source-frame mass, would therefore absorb the unknown magnification with the true distance and bias the result; masses are reported in the detector frame instead to avoid this.

\subsection{Recovering the true source-frame mass with an assumed lens model}
\label{sec:lens_model_recovery}

Recovering the true source distance, and hence the true source-frame mass, requires resolving the magnification-distance degeneracy identified above. For a general lens model this is not possible from the two apparent distances alone: even a full reconstruction of the lens from all its lensed-image observables leaves residual degeneracies, such as an overall similarity transformation, that can only be broken with electromagnetic follow-up of the identified lens galaxy (its redshift and Einstein radius, plus an independent mass estimate from its velocity dispersion) \cite{Poon2025_lens_reconstruction}. Since this is a simulation-only study, no such follow-up exists, and substituting \textsc{LeR}'s known lens truth in its place would be circular, recovering the injected value by construction rather than testing a method.

Instead, the degeneracy is broken by assuming a simple, generic lens model \cite{Kim2024_lensing_distance}, reducing the unknowns to a single free parameter: the source position $y$ relative to the lens's optical axis. In the geometric optics limit, the magnifications of the two images of a point-mass (PM) or singular isothermal sphere (SIS) lens are
\begin{equation}
\mathrm{PM:}\ \ \mu_\pm(y) = \frac{1}{2}\left(\frac{y^2+2}{y\sqrt{y^2+4}} \pm 1\right),
\qquad
\mathrm{SIS:}\ \ \mu_+(y) = 1+\frac{1}{y},\ \ |\mu_-(y)| = \frac{1}{y}-1 \quad (y<1).
\label{eq:lens_mu}
\end{equation}
The relative magnification $\mu_{\mathrm{rel}}=|\mu_-/\mu_+|$ is measurable directly from the two apparent distances already in the joint posterior, without any external information,
\begin{equation}
\mu_{\mathrm{rel}} = \left(\frac{D_{L,+}^{\mathrm{eff}}}{D_{L,-}^{\mathrm{eff}}}\right)^2,
\label{eq:mu_rel}
\end{equation}
where the ``+'' image is defined, per event, as the one with the smaller apparent distance. Equations~\eqref{eq:lens_mu} and \eqref{eq:mu_rel} are inverted numerically to solve for $y$, which is then substituted back into the corresponding expression for $\mu_+(y)$ to obtain a corrected true distance $D_L=\sqrt{\mu_+}\,D_{L,+}^{\mathrm{eff}}$, from which the source-frame chirp mass is recomputed as in the naive case above.

Figure~\ref{fig:source_mass_recovery} shows the resulting bias for both models, evaluated with only the joint posterior's own apparent distances, never the injected truth. Unlike the naive bias, which is positive for every event, the corrected bias takes both signs, so the median alone can partly reflect cancellation between events corrected too much and events corrected too little, rather than a genuine reduction. The median absolute bias, $\widetilde{|y|}$, avoids this and is used here as the main summary statistic: the naive bias corresponds to $\widetilde{|y|}\approx11.5\,M_\odot$ (Figure~\ref{fig:source_mass_bias_vs_injected}, where every residual has the same sign), the point-mass correction reduces this to $\widetilde{|y|}=6.18\,M_\odot$ ($\tilde{y}=5.86$, $\sigma=6.33$), and the SIS correction reduces it further to $\widetilde{|y|}=4.34\,M_\odot$ ($\tilde{y}=3.52$, $\sigma=5.62$).

\begin{figure}[h!]
    \centering
    \includegraphics[width=\linewidth]{Figures/source_mass_recovery.png}
    \caption[Source-frame chirp mass bias after lens-model correction]{Bias of the source-frame chirp mass after correcting for magnification with an assumed point-mass (\textit{left}) or SIS (\textit{right}) lens model, against the injected source-frame chirp mass, for all 150 events.}
    \label{fig:source_mass_recovery}

The SIS correction outperforms the point-mass correction on both statistics, consistent with \textsc{LeR}'s true lens model being an EPL profile with external shear (Table~\ref{tab:LER_params}, $\gamma\sim\mathcal{N}(2.0,0.2)$), structurally closer, on average, to an isothermal profile than to a point mass. Neither model brings the bias down to the noise level seen in the detector-frame chirp mass residual ($\sigma\approx2\,M_\odot$, Figure~\ref{fig:residuals_mass}); what remains comes from the difference between the simple, round lens assumed here and the true elliptical, sheared lens of each event.
